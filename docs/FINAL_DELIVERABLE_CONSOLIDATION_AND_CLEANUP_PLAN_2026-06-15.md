# Final Deliverable Consolidation And Cleanup Plan

Created: 2026-06-15

## Purpose

This plan stops the Word/PowerPoint/website direction from splitting into
another set of competing versions. It reviews the current local deliverables,
Drive copies, rule-book documents, website state, and project base, then
defines what to keep, what to pull forward, what to archive, and what should be
deleted only after explicit approval.

No approved well-log rows, core rows, restricted identifiers, trained models,
model metrics, occurrence probabilities, saturation predictions, hydrate proof,
or sweet-spot rankings are part of this cleanup plan.

## Current Situation

The project has too many files named or treated like "final" deliverables. The
names are misleading because each version solved a different problem:

- June 11/12 Gmail-style decks solved the visual rhythm problem.
- June 13 science-to-ML rebuild solved the source-backed method spine.
- June 15 stability/ML remake was rejected because it narrowed the project too
  much.
- June 15 diagram-first workflow deck was rejected because it changed too much
  of the prior Gmail deck.
- V5/V5.2 solved the method architecture and schema-readiness story, but the
  deck is too diagram/poster-heavy and its newer slide topics are not the final
  presentation sequence by themselves.
- The website now has useful skeleton panels, but it is not the main
  deliverable and should not drive the final Word/slide story.

The correct final direction is:

```text
original nine-slide topic spine + Gmail visual authority + V5.2 method content
+ Word-first method spine
```

The original/main slide topics are the topic authority. V5.2 supplies updated
method decisions, schema/ML architecture details, and intact complex
architecture slides, but it must not rename the deck into a V5.2
workflow-poster sequence.
