## Best Sources By Well

### Mount Elbert

The strongest Mount Elbert source set is Rose et al. (2011) for coring/lithostratigraphy, Winters et al. (2011) for core physical properties, Lee and Collett (2011) for log-derived saturation comparison, and Collett et al. (2011) plus LDEO LogDB for log/core montage and wireline inventory. These sources can support a realistic Slide 3 log/lithology panel and the ML ledger, but all saturation estimates remain target/calibration fields rather than predictor inputs.

### Ignik Sikumi

The strongest Ignik Sikumi source set is Boswell et al. (2017) for the field experiment identity and reservoir context, the NETL field-trial/review pages for public operational and well-log display metadata, and the OSTI/NETL ML report for Well-IGS alias and log-family context. This is weaker than Mount Elbert for public core data; it is currently best treated as a log/NMR-derived calibration case until header-only workbook metadata confirms actual core or pressure-core columns.

### Hydrate-01

The strongest Hydrate-01 source set is Boswell et al. (2022) for the scientific overview, Collett et al. (2022) for planning/LWD/sidewall pressure coring, Haines et al. (2022) for sonic/resistivity/NMR saturation comparison, Tamaki et al. (2022) for geologic reservoir characterization, and Yoneda et al. (2021, 2022) for pressure-core physical properties, NMR, and permeability. The Mendeley dataset is a useful retrieval target but raw tables belong in Drive/OSL, not GitHub.

### HYDRATE 02

The strongest HYDRATE 02 source set is Yoneda et al. (2026) for NMR T2 permeability, the ACS Figshare supplement collection for that paper, Hiruta et al. (2026) for sedimentology/geochemistry and grain-size/mineralogy context, Yoneda et al. (2026) permeability evolution for pressure-core permeability behavior, and Aung et al. (2026) for LWD acquisition/QC. The Phillips lithological-control paper and the Collett/Marsteller operations/data paper are high-value retrieval targets but need exact DOI/page confirmation before becoming primary ledger entries.

## ML Pipeline Use

- Measured log/core/lithology fields can support `X_allowed` only if they are independently measured, unit-checked, depth-aligned, and cleared by the approved-runtime leakage review.
- Hydrate saturation, pressure-core saturation, NMR-derived saturation, interpreted hydrate labels, and occurrence calls are target/calibration/validation fields. They must never be listed as predictor inputs.
- Permeability is mainly a producibility and reservoir-review context field. It can help evaluate whether a hydrate-bearing interval might behave like a producible sand system, but it does not prove hydrate occurrence.
- Core lithology, grain size, mineralogy, and facies descriptions support reservoir-quality and facies calibration. They are the best bridge between the Slide 3 log-panel story and the approved-runtime ML feature ledger.
- Depth alignment must preserve original depth units, source-depth columns, matching/interpolation rules, and any offset flags. Depth can remain an alignment/context axis unless mentor approval changes its feature role.
- Public GitHub outputs should store source metadata, citation links, headers, field-family tags, source-role notes, and sanitized retrieval queues only. Raw workbooks, pressure-core tables, downloaded supplements containing measurement rows, and approved-runtime labels remain Drive/OSL-only.
